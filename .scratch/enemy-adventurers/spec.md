# Spec: Enemy Adventurers

Status: ready-for-agent

The Enemy Adventurer system: the Codex Class hierarchy and linear stat formula, the Fixed 12-Turn Action Cycle and permanent cycle Action Tags, the Unit Skill hierarchy (`MoveSkill`, `AttackSkill`, `ActiveSkill`, `PassiveSkill`) with `Skill Countdown` and three-phase `SPD`-ordered `Action Time` execution, unit-by-unit constant-speed Move Skill glides stopping on collision, skill-driven collision damage (`(J / 40) * hitter.POW`), per-puck collision history, Pocket Area return at next `Action Time`, and seeded Stage generation. Vocabulary per `CONTEXT.md` and `.docs/contexts/battlefield.md`; movement and damage-channel rules per ADR-0001 and ADR-0002.

## Problem Statement

Enemy Adventurers are the player's primary opposition on the Cue Table, yet today they are a throwaway prototype: a shared wander/chase/attack state machine with hard-coded stats running continuously during a placeholder 5-second timer, with no connection to the 12-Turn Action Cycle, no permanent cycle Action Tags on the Time Board, no Class Codex stat growth, and no Unit Skill system. Collision rules for Guard were previously hardcoded by class rather than driven by skills, collision damage ignored unit `POW`, pocketed pucks respawned immediately instead of waiting for their next `Action Time` (except Boss Monsters), and `Hit Level` reset every turn rather than building across the 12-turn Action Cycle. Without the real Enemy Adventurer system, neither Single-Player PvE nor 2-Player Versus battles have authentic tactical rhythm, skill interactions, or readable turn planning.

## Solution

Replace the prototype enemy AI wholesale with a data-driven **Class Codex Registry**, a **Unit Skill System** (`UnitSkillManager`), an **Auto Fight Manager** (`AutoFightManager`) paired with a **Presentation Manager** (`PresentationManager`), and a **Fixed 12-Turn Action Cycle** integrated across both Single-Player PvE and 2-Player Versus battles:

1. **Class Codex Registry, Linear Stat Formula & Statistic Buff/Debuff Pipeline**: The 28 Rank 1–3 Classes across the four Class Trees (`Guard`, `Brawler`, `Scout`, `Acolyte`) compute base `HP`, `POW`, and `SPD` from the Codex linear formula `{base HP}/{base POW}/{base SPD} + {HP/lv}/{POW/Lv}/{SPD/Lv}` (`stat = base + Lv * per_lv`), inheriting `puck mass`, `puck radius`, `stat` formula, `Action Countdown` (`4` for Guard/Brawler trees, `3` for Scout tree, `6` for Acolyte tree), and `Base Skills` from their `From` prerequisite class unless overridden. In demo battles, Adventurers default to **Unit `Lv = 5`** and **Skill `Lv = 1`** with all base skills equipped (`Lv 5` base stats: Guard `3500 HP / 280 POW / 125 SPD`, Brawler `2800 HP / 280 POW / 160 SPD`, Scout `2800 HP / 280 POW / 145 SPD`, Acolyte `2100 HP / 280 POW / 140 SPD`), and Boss Monsters use **`POW = 400`** for testing. `UnitInformationDO` stores both `Lv`-scaled base stats (`base_max_hp`, `base_power`, `base_spd`) and effective stats (`max_hp`, `power`, `spd`), recalculated via `round(base_stat_at_lv * (1 + sum_pct) + sum_flat)` whenever a Statistic Buff/Debuff activates or deactivates.
2. **Battlefield Managers (`UnitSkillManager`, `AutoFightManager`, `PresentationManager`) & `Skill Display` UI**:
   - **`UnitSkillManager`**: manages skill types and unit ownership, common skill effects (`Statistic Buff/Debuff`, `Pocket Area Damage +/-?%`, `On the cue table`, `Skill Countdown`), cross-unit skill effects, and a **trigger-time-to-skills map** so trigger points only evaluate skills registered for that trigger time without scanning all skills.
   - **`AutoFightManager`**: controls the automated flow in `Action Time` and `Settle Time` for all units (not only Adventurers).
   - **`PresentationManager`**: controls visual/sound effects and animations across `Action Time` and `Settle Time` (respecting `TimingManager` Pause and Fast Play).
   - **`Unit Detail Display` & Hover `Skill Display`**: The bottom of `Unit Detail Display` shows two rows of skill icons — Row 1 with 3 slots (`Move | Attack | Active`, leaving an empty slot frame when no Active Skill is equipped) and Row 2 with all `Passive` Skills (plus live countdown/counter badges). Hovering a skill icon opens a **`Skill Display`** popup showing `name`, `type`, `skill Lv`, and the skill's `Description` (never raw `Effects`) injected with resolved variable values (`?X`, `?Y` highlighted in Value colour) and `*keyword*` terms (highlighted in Keyword colour), with the meanings of those keywords listed at the bottom.
2. **Fixed 12-Turn Action Cycle & Cycle Action Tags**: Every 12 Turns is an Action Cycle. Cycle Action Tags always sit at turns **`3, 4, 6, 8, 9, 12`** of each repeating 12-turn cycle (even when `0` units act on that turn, with `12`-interval tags highlighted in a special colour). Every non-defeated Adventurer contributes `+1` to all multiples of its fixed `Action Countdown` (`3`, `4`, or `6`), regardless of team or whether it is currently pocketed. On the Time Board, each tag displays an arrow (plus a circle on top showing the acting unit count for tags on the upper bar within 10 Turns when `count > 0`; when `count == 0`, the circle and number disappear; no turns-to-goal integer is shown on the Time Board tag itself). Each unit's personal `Action Countdown` is shown on its `Unit Display`. When a cycle tag with `count == 0` reaches the goal, it clears without entering `Action Time`; when `count > 0`, `Action Time` triggers.
3. **Three-Phase `SPD`-Ordered Skill Execution in `Action Time`**: In `Action Time`, all on-table acting units whose `Action Countdown` reached `0` execute across three sequential skill phases — **all Active Skills first, then all Attack Skills, then all Move Skills** (rather than executing all skills of one unit before the next). Within each phase, acting units are ordered by **`SPD` descending** (tie-broken by their order in the game). Triggered Attack and Active Skills play in `SPD` order with a `~0.30s` stagger and `~0.70s` animation duration, pushing their `Damage DO` and applying any `Hit Level+X` before `Settle Time`. Any unit whose triggered Active or Attack Skill has `Skip Movement` skips the Move Skill phase.
4. **Unit-by-Unit Constant-Speed Move Skill Glides**: In the Move Skill phase, remaining acting units execute their Move Skill **unit by unit** (ordered by `SPD` descending, tie-broken by game order) at constant glide speed. Move Skill distance checks default to **centre-to-centre**. A gliding puck stops its glide immediately once it collides with another puck or a Cushion (dealing no collision damage or impulse) and never enters or comes to rest on a Pocket Area.
5. **Pocket Return Lifecycle**: When a puck falls into a Pocket Area and survives `Settle Time`:
   - A **Boss Monster** respawns at the end of **that turn's `Settle Time`** at a random empty, non-pocket Tile inside the middle 80% of the Cue Table so the game can continue.
   - An **Adventurer** (or Minion) stays off the table with its `Unit Display` greyed out while keeping its normal `Action Countdown` and Time Board `Action Tag` counts unchanged. At its **next `Action Time`**, after all on-table acting units finish moving, it returns to the table at a random empty, non-pocket Tile inside the middle 80% of the Cue Table (ordered by `SPD` descending if multiple units return on the same turn), which **consumes its action for that turn**.
6. **Skill-Driven Collisions, `(J / 40) * hitter.POW` Collision Damage, Collision History & 12-Turn `Hit Level` Reset**:
   - All hardcoded class-based collision rules are removed: by default, Boss Monsters take `0` collision damage from puck impacts, while all non-Boss pucks take collision damage equal to **`(J / 40) * hitter.POW`** (where `J` is the collision Impulse scalar applied to the victim puck and `hitter.POW` is the hitting unit's `POW`).
   - Every non-Boss unit puck gains **`Hit Level +1`** when hitting a Cushion during `Puck-puck Time!`.
   - `Hit Level` persists across turns and resets to `0` **only after the `Settle Time` of Turn 12** (the end of each 12-turn Action Cycle), while `Damage Stack` settles/clears and `Frenzy Power` decays (`(current_frenzy / 2) + 50%`) at every `Settle Time`.
   - Each puck records an ordered **Collision History** of pucks and cushions collided during the turn, cleared at the end of `Settle Time`.
   - Guard's `SPA10001 Protect` reduces an opponent Boss Monster's Frenzy Power on hit by `Y% = X * (4% + Lv * 1%)` (where `X` is the number of non-defeated non-Guard-tree teammates in the same Adventurer Team, including pocketed teammates, offsetting the normal `+10%`; doubled to `2 * Y%` if this Guard puck is the very first puck in the Boss Monster's collision history for that shot), and reduces collision damage taken on both pucks by **`50%` (fixed, applied at most once per collision)** when colliding with a same-team ally.
   - Brawler's `SPA10002 Heavy Hit` (`Lv 1..3`) is equipped as Brawler's base passive skill with an empty (`TBC`) effect body for now.
   - Scout's `SPA10003 Safety Rope` reduces Pocket Area damage by `-(10 + Lv * 3)%` for teammates in the same Adventurer Team while that Scout is on the cue table (excluding the falling Scout itself if it falls into a pocket).
   - Acolyte's `SPA10004 Chanting` (`Lv 1..3`) increments its skill counter `N` by `+1` at the start of each `Action Time` of the Acolyte and increases the Acolyte's `POW` by `X% = N * (7.5 + Lv * 2.5)%` via the Statistic Buff/Debuff pipeline; the counter `N` resets to `0` if the Acolyte falls into a Pocket Area, and skips the counter increment on the `Action Time` when the Acolyte returns from a Pocket Area.

## User Stories

### Visual Identity, Unit Display & Action Tags

1. As a player, I want to see each Adventurer's portrait, Class Mark, HP bar, Reference Mark (`G, B, S, A, F, E` / `g, b, s, a, f, e`), and Class Tree colour in the Unit Information Board, so that I can read the enemy team at a glance.
2. As a player, I want each Adventurer's Unit Display to show its personal Action Countdown turns remaining until its next action, so that I know when each specific unit will act.
3. As a player, I want every Adventurer to have a fixed Action Countdown that is a factor of 12 (`3` for Scout tree, `4` for Guard and Brawler trees, `6` for Acolyte tree, modifiable by passive skills to another fixed factor), so that Action Time only occurs at predictable cycle turns (`3, 4, 6, 8, 9, 12`).
4. As a player, I want cycle Action Tags to always appear at turns `3, 4, 6, 8, 9, 12` of each repeating 12-turn Action Cycle on the Time Board (even when `0` units act on that turn), with `12`-interval tags highlighted in a special colour, so that the 12-turn rhythm and the Turn 12 climax are always visible.
5. As a player, I want every non-defeated Adventurer (across all teams, including while pocketed) to contribute `+1` to every cycle Action Tag at multiples of its Action Countdown (`3, 4, 6, 8, 9, 12`), so that tag counts accurately predict future turn density.
6. As a player, I want each Time Board Action Tag to display an arrow plus a circle on top showing the acting unit count when the tag is within 10 Turns (on the upper bar) and its count is `> 0`, and to hide the circle and number when its count is `0` (or while on the lower bar), without showing a redundant turns-to-goal integer on the Time Board tag itself, so that the Time Board stays clean and readable.
7. As a player, when a cycle Action Tag with a `0` unit count reaches the goal slot on the Time Board, I want it to clear immediately without triggering `Action Time`, so that the battle never pauses for an empty action turn.
8. As a player, I want a defeated Adventurer's Unit Display greyed out with a red cross and its HP bar, Damage Stack badge, and Action Countdown hidden, and its contribution removed from future Time Board Action Tag counts at `Settle Time`, so that I immediately know it is out of the battle.

### Pocket Return Lifecycle

9. As a player, when an Adventurer falls into a Pocket Area and survives `Settle Time`, I want its Unit Display to turn grey while keeping its HP bar, its personal Action Countdown, and the Time Board Action Tag counts unchanged, so that I know it is still alive and remains on its normal action schedule.
10. As a player, when a pocketed Adventurer's next `Action Time` arrives, I want it to return to the Cue Table (at a random empty, non-pocket Tile inside the middle 80% of the table) **after all on-table acting units finish moving**, ordered by `SPD` descending if multiple pocketed units return on the same turn, and I want returning from the pocket to **consume its action for that turn** (skipping Active, Attack, and Move skills that turn), so that pocketing an enemy meaningfully delays its next attack or move by one full cycle interval.
11. As a player, when my Boss Monster falls into a Pocket Area and survives the 50% 1-bar Pocket Area damage in `Settle Time`, I want the Boss Monster puck to respawn on the Cue Table (at a random empty, non-pocket Tile inside the middle 80% of the table) at the end of **that turn's `Settle Time`**, so that the game can always continue on the next turn.

### Three-Phase `SPD`-Ordered Action Time & Skill Countdowns

12. As a player, when a cycle Action Tag with count `> 0` reaches the goal and triggers `Action Time`, I want all on-table acting Adventurers (whose Action Countdown reached `0`) to execute their skills across three sequential phases — **all Active Skills first, then all Attack Skills, then all Move Skills** — rather than one unit running all of its skills before the next unit, so that combat phases resolve in a clear, structured order.
13. As a player, within each of the three skill phases (`Active`, `Attack`, `Move`), I want the acting units ordered by their **`SPD` (speed) stat from highest to lowest**, with ties broken by their order in the game (spawn / registration order), so that faster classes and higher-level units act first within every phase.
14. As a player, I want each skill with a `Skill Countdown` (such as Guard's `SAA10001 Lance` with `Skill Countdown: 9` and Acolyte's `SAA10004 Spell Attack` with `Skill Countdown: 12`) to start at its full countdown value at Wave start, tick down by `1` every Turn (including while the unit is pocketed, clamping at `0`), and reset to its full countdown value **only when the skill's conditions are met and it activates**, so that long-cooldown skills require multiple turns to charge and wait at `0` until a valid target is in range.
15. As a player, when multiple units trigger Attack or Active Skills in `Action Time`, I want their skill animations to play in `SPD` descending order with a readable testing cadence (`~0.30s` stagger between activations, `~0.70s` animation duration), pushing their `Damage DO` and applying `Hit Level+X` near the end of the animation before `Settle Time`, so that I can visually follow who attacked whom.
16. As a player, whenever an acting unit triggers an Active or Attack Skill marked `Skip Movement` (`SAA10001 Lance`, `SAA10002 Melee`, `SAA10004 Spell Attack`), I want that unit to skip the Move Skill phase for that `Action Time`, whereas skills without `Skip Movement` (Scout's `SAA10003 Shoot`) evaluate and fire from the unit's starting position in the Attack Skill phase and then allow the unit to move in the Move Skill phase.
17. As a player, at the end of `Settle Time` following `Action Time`, I want every Adventurer that acted (or returned from a pocket) to reset its personal Action Countdown to its fixed interval (`3`, `4`, or `6`), so that the 12-turn cycle repeats seamlessly.

### Base Move Skills (`SMA10001..10004`) & Unit-by-Unit Glide Rules

18. As a player, in the Move Skill phase of `Action Time`, I want moving units to execute their constant-speed scripted glides **unit by unit** in `SPD` descending order (tie-broken by game order), and I want any gliding puck to **stop its glide immediately upon colliding with another puck or a Cushion** (without applying impulse or collision damage) and never enter or stop on a Pocket Area, so that movement never causes overlaps or unintended physics chain reactions.
19. As a player, I want all distance checks in Move Skills to be measured **centre-to-centre** by default, while Attack Skills follow their Codex specification (edge-to-edge for `Lance` and `Melee`; centre-to-centre for `Shoot`).
20. As a player, I want Guard's `SMA10001 Block` (`Lv 1..3`, `Dist: 0.0-1.3 + Lv * (0.0-0.2)`) to check if there are friendly on-table units of the Scout or Acolyte Class Trees: if so, calculate the line segments between the opponent's Boss Monster and those allies, pick a random target point on those segments within the $180^\circ$ front half-plane of the Boss Monster (avoiding moving past the Boss) that is close to the Guard, and glide toward it; if no such allies are on the table, glide toward a random position within distance `1.0..3.0` (centre-to-centre) around the opponent's Boss Monster.
21. As a player, I want Brawler's `SMA10002 Approach` (`Lv 1..3`, `Dist: 0.8-1.0 + Lv * (0.0-0.2)`) to glide toward the nearest opponent puck on the table at a random angle within $90^\circ$ ($\pm 45^\circ$ of the direct vector to that target).
22. As a player, I want Scout's `SMA10003 Patrol` (`Lv 1..3`, `Dist: 0.8-1.0 + Lv * (0.0-0.2)`) to check the centre-to-centre distance to the opponent's Boss Monster: if `< 4.5`, glide away within a $60^\circ$ angle ($\pm 30^\circ$); if `> 6.0`, glide closer within a $60^\circ$ angle ($\pm 30^\circ$); otherwise (`4.5..6.0`), glide in a random $360^\circ$ direction.
23. As a player, I want Acolyte's `SMA10004 Move Away` (`Lv 1..3`, `Dist: 1.5-2.0 + Lv * (0.0-0.2)`) to check whether the opponent's Boss Monster is on the left ($X < 0$) or right ($X \ge 0$) of the Cue Table: if the Acolyte is already inside the farthest `width = 2.0` area on the opposite side, stay still; otherwise glide toward that far area within a $60^\circ$ angle ($\pm 30^\circ$).

### Base Attack Skills (`SAA10001..10004`)

24. As a player, I want every Attack Skill's raw damage to equal `unit.POW * skill_ratio` (pushed as a scalable `Damage DO` to the target's Damage Stack in `Action Time`) and to increase the target's `Hit Level` by the skill's `Hit Level+X` before `Settle Time` resolves.
25. As a player, I want Guard's `SAA10001 Lance` (`Lv 1..11`, `Skill Countdown: 9`, `Ratio: (90 + Lv * 10)%`, `Hit Level+2`, `Skip Movement`) to check all opponent pucks on the table, and if any are within `3.5` distance (edge-to-edge), attack one random opponent puck within range (lunge/lance animation toward target).
26. As a player, I want Brawler's `SAA10002 Melee` (`Lv 1..11`, no Skill Countdown, `Ratio: (90 + Lv * 10)%`, `Hit Level+1`, `Skip Movement`) to check the nearest opponent puck on the table, and if it is within `1.5` distance (edge-to-edge), attack it (sword swipe animation toward target).
27. As a player, I want Scout's `SAA10003 Shoot` (`Lv 1..11`, no Skill Countdown, `Ratio: (45 + Lv * 5)%`, `Hit Level+1`, does **not** skip movement) to check all opponent pucks on the table from the Scout's starting position in the Attack Skill phase, and if any are within `7.5` distance (centre-to-centre), attack one random opponent puck within range (arrow projectile animation toward target) before the Scout moves in the Move Skill phase.
28. As a player, I want Acolyte's `SAA10004 Spell Attack` (`Lv 1..11`, `Skill Countdown: 12`, `Ratio: (225 + Lv * 25)%`, `Hit Level+3`, `Skip Movement`) to attack the opponent's Boss Monster from anywhere on the table (magic projectile animation toward target).

## Implementation Decisions

- **Rebuild Prototype Enemy AI Wholesale**:
  - Discard the legacy continuous `WANDER / CHASE / ATTACK` physics-process state machine on enemy pucks and the temporary `Action` button / 5-second `Action Time` placeholder timer on the demo battlefield. Enemy Adventurer pucks never self-propel via continuous `_physics_process` steering; they move only when driven by `PuckVelocityManager` during `Puck-puck Time!` or by the `Action Time` skill executor during the Move Skill phase.
- **Class Codex Registry (`ACG10001..ACA30004`) & Linear Stat Calculator**:
  - Model all 28 Rank 1–3 common classes from `.docmanual/codexList/classes/` (`guard.md`, `brawler.md`, `scout.md`, `acolyte.md`) plus an extensible hook for `others.md` (Exceptional Classes).
  - Each class entry holds: `class_id` (e.g. `"ACG10001"`), `name_key`, `class_tree` (`GUARD`, `BRAWLER`, `SCOUT`, `ACOLYTE`, `OTHERS`), `rank` (`1..5`), `from_class_id`, `action_countdown` (`4` for Guard/Brawler trees, `3` for Scout tree, `6` for Acolyte tree), `mass`, `radius`, `base_hp`, `base_pow`, `base_spd`, `hp_per_lv`, `pow_per_lv`, `spd_per_lv`, and `base_skill_ids`.
  - Any Rank 2 or Rank 3 class whose `mass`, `radius`, or `stat` formula is not explicitly specified inherits those values by walking its `from_class_id` chain back to its Rank 1 Base Class, and inherits Base Passive Skills from its prerequisite chain.
  - Stat calculation for an Adventurer of level `unit_lv >= 1`:
    - `base_max_hp = base_hp + unit_lv * hp_per_lv`
    - `base_power = base_pow + unit_lv * pow_per_lv`
    - `base_spd = base_spd + unit_lv * spd_per_lv`
  - Add `unit_lv: int` (default `5` in demo battles), `base_max_hp: int`, `base_power: int`, `base_spd: int`, `spd: int`, and `stat_modifiers: Array[Dictionary]` (`{"id": String, "stat": "max_hp" | "power" | "spd", "pct": float, "flat": int}`) to `UnitInformationDO`. Whenever a Statistic Buff/Debuff activates or deactivates, recalculate `stat = int(round(float(base_stat) * (1.0 + sum_pct) + float(sum_flat)))` (clamping `current_hp = mini(current_hp, max_hp)` if `max_hp` decreases). Set demo Boss Monster default `power = 400` (`base_power = 400`).
- **Battlefield Managers (`UnitSkillManager`, `AutoFightManager`, `PresentationManager`)**:
  - **`UnitSkillManager`** (in group `"unit_skill_manager"`): owns the skill registry, instantiates and attaches `UnitSkill` instances to `UnitInformationDO`, maintains a **trigger-time-to-skills map** (`Dictionary[String, Array]` keyed by trigger times: `ON_CREATED`, `ON_PUCK_COLLISION`, `ON_CUSHION_COLLISION`, `ON_POCKET_FALL`, `ON_POCKET_RETURN`, `ON_DAMAGE_DEALT`, `ON_DAMAGE_RECEIVED`, `ON_UNIT_DEFEATED`, `ON_ACTION_TIME_START`, `ON_BEFORE_MOVE`, `ON_AFTER_MOVE`, `ON_BEFORE_ATTACK`, `ON_AFTER_ATTACK`, `ON_CARD_PLAYED`, `ON_CUE_SHOT`, `ON_CARD_COMPLETED`, `ON_CARD_DRAWN`) so event sites query only the skills registered for that trigger time without scanning all skills, and provides common skill effect helpers (`On the cue table`, `Pocket Area Damage +/-?%`, `Statistic Buff/Debuff`, `Skill Countdown` ticking).
  - **`AutoFightManager`** (in group `"auto_fight_manager"`): controls the automated flow in `Action Time` (start-of-action passives like `SPA10004 Chanting`, then Phase 1 Active Skills, Phase 2 Attack Skills, Phase 3 Move Skills unit-by-unit, Phase 4 Pocketed Units Return) and `Settle Time` (damage settlement, Boss pocket respawn, Action Countdown resets, Turn-12 `Hit Level` reset) for all units on the battlefield.
  - **`PresentationManager`** (in group `"presentation_manager"`): controls visual/sound effects and animations (attack projectiles/swipes, constant-speed Move Skill glides, `UnitDisplay` skill popups, Frenzy Power spread, settled `-567` HP popups) across `Action Time` and `Settle Time`, respecting `TimingManager` Pause and Fast Play (with an instant/headless option for unit tests).
- **Unit Skill Hierarchy (`UnitSkill` → `MoveSkill`, `AttackSkill`, `ActiveSkill`, `PassiveSkill`) & `Skill Display` UI**:
  - Base `UnitSkill` data/logic object holds: `skill_id` (`SMA10001`, `SAA10001`, `SPA10001`, etc.), `name_key`, `description_key`, `icon_path`, `skill_category` (`"move" | "attack" | "active" | "passive"`), `trigger_times: Array[String]`, `is_base_skill: bool`, `skill_lv: int` (default `1`), `max_lv: int`, `max_countdown: int` (`0` if no Skill Countdown), `current_countdown: int` (initialized to `max_countdown` at Wave start, never `0` if `max_countdown > 0`), `counter: int` (for counter skills like `SPA10004 Chanting`), and `skip_movement: bool`.
  - Default Base Class skill loadouts (all equipped at `skill_lv = 1` in demo battles):
    - **Guard (`ACG10001`)**: `SMA10001 Block`, `SAA10001 Lance` (`max_countdown = 9`, `skip_movement = true`, `Hit Level+2`, `ratio = (90 + 10 * Lv)%`), `SPA10001 Protect`
    - **Brawler (`ACB10001`)**: `SMA10002 Approach`, `SAA10002 Melee` (`max_countdown = 0`, `skip_movement = true`, `Hit Level+1`, `ratio = (90 + 10 * Lv)%`), `SPA10002 Heavy Hit` (TBC empty effect)
    - **Scout (`ACS10001`)**: `SMA10003 Patrol`, `SAA10003 Shoot` (`max_countdown = 0`, `skip_movement = false`, `Hit Level+1`, `ratio = (45 + 5 * Lv)%`), `SPA10003 Safety Rope`
    - **Acolyte (`ACA10001`)**: `SMA10004 Move Away`, `SAA10004 Spell Attack` (`max_countdown = 12`, `skip_movement = true`, `Hit Level+3`, `ratio = (225 + 25 * Lv)%`), `SPA10004 Chanting` (`counter N` increments by `+1` at start of each on-table Action Time of this unit, applying `+N * (7.5 + 2.5 * Lv)%` POW buff; resets `N = 0` on Pocket Area fall; skips increment on pocket return turn)
  - **`UnitDetailDisplay` Skill Icons & Hover `Skill Display`**:
    - Bottom of `UnitDetailDisplay` renders two icon rows: Row 1 has 3 spaced icon slots for `Move`, `Attack`, and `Active` Skills (rendering an empty slot frame in the 3rd slot when no Active Skill is equipped); Row 2 renders all `Passive` Skill icons. Icons display a live badge when `max_countdown > 0` or `counter > 0`.
    - Hovering a skill icon opens a `Skill Display` tooltip window showing localized skill `name`, `type`, `skill Lv`, and a styled `Description` (`RichTextLabel` BBCode) where `?X`/`?Y` placeholders are injected with their resolved values in a **Value colour** and `*keyword*` tokens are highlighted in a **Keyword colour**, followed by the localized definitions of those keywords at the bottom (never displaying internal `Effects` implementation text).
- **Fixed 12-Turn Action Cycle & Time Board Cycle Tags**:
  - Track the battle's turn counter within the repeating 12-turn Action Cycle (`cycle_turn: 1..12`).
  - Cycle Action Tags always exist on the Time Board at turns corresponding to `3, 4, 6, 8, 9, 12` of each repeating 12-turn cycle (with `12`-interval tags flagged for special highlight colour).
  - For any cycle tag at `k` turns from the goal, its `count` is the total number of non-defeated Adventurers (across all teams, including pocketed Adventurers) whose `Action Countdown` divides that tag's cycle turn (equivalently, whose personal `next_action_turns` will hit `0` at that slot).
  - On the Time Board view:
    - Every cycle tag slot renders its arrow (with `12`-interval arrows highlighted).
    - If the tag is on the **upper bar (within 10 turns of the goal)** and `count > 0`, render a circle on top of the arrow with the `count` integer inside.
    - If `count == 0` (or the tag is on the lower bar, `> 10` turns away), hide the circle and count number. Do not render a turns-to-goal integer on the Time Board tag.
  - When a Turn completes in `Charging Time`:
    - All non-defeated Adventurers decrement their `next_action_turns` by `1`, and all skills with `current_countdown > 0` decrement `current_countdown` by `1` (clamping at `0`, even while the owning unit is pocketed).
    - If a cycle tag reaches the goal slot with `count == 0`, it is removed immediately and `Charging Time` continues without entering `Action Time`.
    - If a cycle tag reaches the goal slot with `count > 0` (i.e. one or more non-defeated units have `next_action_turns == 0`), `TimingManager` transitions to `Action Time`.
- **Three-Phase `SPD`-Ordered Action Time Executor**:
  - Partition units with `next_action_turns == 0` into:
    - `on_table_units`: non-defeated, non-pocketed units with at least one active puck on the Cue Table.
    - `returning_pocketed_units`: non-defeated, currently pocketed units (`is_pocketed == true`).
  - Sort both lists by `u.spd` **descending**, tie-broken by their registration / spawn order in the battle.
  - **Phase 1 — All Active Skills**: Iterate `on_table_units` in `SPD` order. For each unit with an equipped `ActiveSkill` whose `current_countdown == 0` and activation condition is met, play its activation (`~0.30s` stagger, `~0.70s` animation duration), reset `current_countdown = max_countdown`, and if `skip_movement == true`, mark the unit as `movement_skipped`.
  - **Phase 2 — All Attack Skills**: Iterate `on_table_units` in `SPD` order. For each unit with an equipped `AttackSkill` whose `current_countdown == 0` and range/target condition is met (evaluated from current puck positions):
    - `SAA10001 Lance`: check all opponent on-table pucks with edge-to-edge distance `<= 3.5`; pick one at random.
    - `SAA10002 Melee`: find nearest opponent on-table puck; require edge-to-edge distance `<= 1.5`.
    - `SAA10003 Shoot`: check all opponent on-table pucks with centre-to-centre distance `<= 7.5`; pick one at random.
    - `SAA10004 Spell Attack`: target opponent's Boss Monster puck (no distance limit).
    - When triggered: play the attack animation (`~0.30s` stagger between units, `~0.70s` duration, scaled by Fast Play), trigger the skill popup on the unit's `UnitDisplay`, reset `current_countdown = max_countdown`, and near the end of the animation push `DamageDO(round_or_float(u.power * ratio), u.unit_id, owner_boss_id, "attack", false)` and call `modify_hit_level(target_unit_id, skill.hit_level_add)`. If `skip_movement == true`, mark the unit as `movement_skipped`.
  - **Phase 3 — All Move Skills (Unit by Unit)**: Iterate `on_table_units` in `SPD` order for units not marked `movement_skipped`. Execute each unit's `MoveSkill` **one unit at a time** before starting the next unit's glide:
    - All distance checks in Move Skills are **centre-to-centre**.
    - Compute desired glide direction and distance `Dist`:
      - `SMA10001 Block`: if friendly on-table Scout-tree or Acolyte-tree pucks exist, consider the line segments between the opponent's Boss Monster and each such ally (restricted to the $180^\circ$ front half-plane of the Boss Monster so the Guard never moves behind the Boss), choose a point on the segment closest to the Guard, and glide toward it by `randf_range(0.0, 1.3) + Lv * randf_range(0.0, 0.2)`; otherwise glide toward a random point at distance `1.0..3.0` around the opponent's Boss Monster.
      - `SMA10002 Approach`: find nearest opponent on-table puck; pick an angle within $\pm 45^\circ$ ($90^\circ$ cone) of the vector toward it; glide by `randf_range(0.8, 1.0) + Lv * randf_range(0.0, 0.2)`.
      - `SMA10003 Patrol`: measure centre-to-centre distance $d$ to opponent's Boss Monster; if $d < 4.5$, pick an angle within $\pm 30^\circ$ ($60^\circ$ cone) away from Boss; if $d > 6.0$, pick an angle within $\pm 30^\circ$ ($60^\circ$ cone) toward Boss; else pick any random $360^\circ$ angle; glide by `randf_range(0.8, 1.0) + Lv * randf_range(0.0, 0.2)`.
      - `SMA10004 Move Away`: check if opponent's Boss Monster is on left ($X < 0$) or right ($X \ge 0$) of the table. Far strip on the opposite side has width `2.0` ($X \in [13.0, 15.0 - r]$ if Boss is on left, or $X \in [-15.0 + r, -13.0]$ if Boss is on right). If already inside that strip, distance is `0` (stay still); otherwise pick an angle within $\pm 30^\circ$ ($60^\circ$ cone) toward that strip and glide by `randf_range(1.5, 2.0) + Lv * randf_range(0.0, 0.2)`.
    - **Stop-on-Collision Ray/Sweep Clamping**: Along the glide segment from start position $\vec{P}_0$ to $\vec{P}_0 + \hat{d} \cdot \text{Dist}$, compute the earliest contact distance $t \in [0, \text{Dist}]$ against any other on-table puck (combined radius $r_1 + r_2$), any Cushion boundary ($\pm(15 - r)$, $\pm(10 - r)$), or any Pocket Area boundary, and truncate the glide distance to $t$ so the puck **stops immediately upon contact** without overlapping. Animate the glide at constant speed.
  - **Phase 4 — Pocketed Units Return**: After all on-table units finish moving, iterate `returning_pocketed_units` in `SPD` descending order. Respawn each unit's puck at a random empty, non-pocket Tile inside the middle 80% of the Cue Table (`set_unit_pocketed(unit_id, false)`). Returning consumes their action for this `Action Time`.
  - When all four phases complete, notify `TimingManager.notify_actions_finished()` (entering `Settle Time` if damage/events occurred, or resetting acted units' `next_action_turns` to their fixed `Action Countdown`).
- **Passive Skill Hooks & Settle Time Rules**:
  - **Per-Puck Collision History**: Each `BasePuck` maintains `collision_history: Array[Dictionary]` recording each puck or cushion collided during the turn (`{"kind": "puck" | "cushion", "target_unit_id": ..., "object": ...}`), cleared at the end of `Settle Time`.
  - **`SPA10001 Protect`**:
    - On Boss Monster collision with an opponent Adventurer puck: after applying the baseline `+10.0%` Frenzy Power, if the struck Adventurer has `SPA10001 Protect`, count `X` = non-defeated non-Guard-tree units in the same Adventurer Team (`u.team_index == struck.team_index` and `u.owner_seat == struck.owner_seat`, including pocketed teammates). Compute `Y = X * (4 + skill_lv * 1)%`. Check if this Guard puck is the very first `"puck"` entry in the hitting Boss puck's `collision_history` for this shot: if so, reduce Boss Frenzy Power by `2 * Y%`, else by `Y%` (clamped to the `50.0%` floor).
    - On Puck–Puck collision between two same-team allies (`_are_units_friendly(u1, u2)` and `u1.team_index == u2.team_index`): if either `u1` or `u2` has `SPA10001 Protect`, multiply the collision damage `(J / 40) * hitter.POW` on **both pucks by `0.5` (`-50%`, applied once even if both have `Protect`)**.
  - **`SPA10003 Safety Rope`**:
    - When a unit `u` falls into a Pocket Area, start from baseline `50%` of `u.max_hp` (1 Health Bar). Sum `-(10 + skill_lv * 3)%` for every unit `ally` in the **same Adventurer Team** (`ally.team_index == u.team_index` and `ally.owner_seat == u.owner_seat`) that has `SPA10003 Safety Rope` AND is currently **on the cue table** (`not ally.is_dead and not ally.is_pocketed` and has at least one puck on the table not falling in a pocket — which excludes `u` itself when `u` falls in). Clamp the resulting percentage to `0%..100%`, compute `ceili(u.max_hp * pct)`, and push as a fixed `DamageDO` (`is_fixed = true`).
  - **Pocket Respawn Separation (Boss vs. Adventurer)**:
    - In `PuckVelocityManager`, when all pucks come to rest at the end of `Puck-puck Time!`, do **not** immediately respawn pocketed Adventurers; instead mark surviving pocketed Adventurers as `is_pocketed = true` in `UnitInformationManager` (keeping their `next_action_turns` and Time Board Action Tag counts intact) so they respawn in Phase 4 of their next `Action Time`.
    - Only a pocketed **Boss Monster** (if not defeated) respawns at the end of that turn's `Settle Time`.
  - **12-Turn `Hit Level` Reset**:
    - `UnitInformationManager.settle_all_damage(reset_hit_level: bool = false)` clears `damage_stack` and decays Boss `Frenzy Power` every `Settle Time`, and resets `hit_level = 0` across all units **only when `cycle_turn == 12`** (the Settle Time of the 12th turn of the Action Cycle).

## Testing Decisions

- **Single Seam: the Headless Battlefield Harness**:
  - Tests instantiate the battle-scoped managers (`TimingManager`, `UnitInformationManager`, `PuckVelocityManager`, `TimeBoard`, `UnitInformationBoard`, and the Adventurer Action / Skill controller) in a headless scene tree, drive the public timing and physics inputs (completing turns, firing collisions/cushion impacts/pocket falls, triggering `Action Time` phases, and completing `Settle Time`), and assert only externally observable domain and view state.
  - A good test asserts external behavior only — Time Board cycle tag counts and circle visibility, unit stats from the Codex formula, `Skill Countdown` values, `SPD`-ordered three-phase skill execution outcomes, post-glide puck positions (stopping on collision), Damage Stack entries (`(J / 40) * POW` and `POW * ratio`), `Hit Level` persistence across turns 1..11 and reset at Turn 12, `SPA10001 Protect` (`2x` first-hit Frenzy reduction and `-50%` ally collision damage), `SPA10003 Safety Rope` pocket damage reduction, and pocketed Adventurer respawn at next `Action Time` vs. Boss Monster respawn at `Settle Time`.

## Out of Scope

- Hero designs (tailor-made superior Adventurers with Exceptional Classes in `others.md`) — the class registry and generation hook support them, but individual Hero designs are future work.
- Unique skills for Rank 2 and Rank 3 Advanced Classes (currently TBC in the Codex; Rank 2 and Rank 3 classes inherit their prerequisite class's stats, mass, radius, Action Countdown, and Base Skills).
- Interruptible **Focusing** skills (all existing Rank 1 base skills `SMA10001..10004` and `SAA10001..10004` take effect immediately in `Action Time` and are non-interruptible; Focusing and collision Interrupts remain hooks for future skills).
- Equipment items, combat-power budget curves across multiple stages, and non-battlefield Codex UI scenes.
